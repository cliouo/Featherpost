## 先看原型

**无需服务的离线版：[Maild-UI-Preview.html](Maild-UI-Preview.html)**。在 Finder 中双击即可打开，CSS 和 JavaScript 已嵌入同一个文件。分享文件时只需这一份，不用启动终端。修改源原型后运行 `python3 docs/design/tauri/build-preview.py` 重新生成。

打开 [prototype/index.html](prototype/index.html)，无需构建、安装依赖或连接邮箱。也可以在仓库根执行：

```sh
python3 -m http.server 4176 --bind 127.0.0.1 --directory docs/design/tauri
```

然后访问 `http://127.0.0.1:4176/prototype/`。顶部细条是**评审工具**，不属于产品界面。可以切换读信、写信、搜索、设置、首次使用及异常情景。

需要长期保留 HTTP 预览时，在 Orca 的 `Maild UI preview` 终端运行服务；不要依赖一次工具调用的日志管道。2026-09-11 曾出现临时进程留存、日志管道失效而返回空响应，已更换为 Orca 管理的终端。离线版不受这个生命周期影响。

建议按以下路径评审：

1. 收件箱 → 选择「沿海来信」HTML 邮件 → 加载本封图片 → 保持原版式阅读。
2. 选择「秋季刊印刷确认」→ 展开历史回复 → 全部回复 → 收起草稿，再打开继续编辑。
3. 写邮件 → 展开抄送/密送 → 留空收件人发送，查看校验 → 输入演示地址 → 模拟发送。
4. 搜索「发票」→ 加附件筛选 → 清空搜索 → 查看「搜索无结果」「索引中」情景。
5. 选择两封邮件 → 查看批量工具栏 → 归档 → 从同步状态查看待同步操作。
6. 设置 → 账户、阅读与隐私、通知与规则、地址与别名、扩展、后台与存储。
7. 首次使用 → 手动 IMAP/SMTP 连接 → 模拟测试 → 开始同步；再看认证失败与结果未知。
8. 切深色；缩窄到 1024、768、375px，检查返回路径和可读性。
9. 顶部“扩展示例” → 允许读取本封 → 写摘录 → 独立窗口打开 → 收回主窗口；侧栏看摘录集，设置中停用示例。

## 方向与取舍

**纸面阅读工作台**：邮件内容占据主要空间，账户/文件夹提供定位，状态平时安静、出错时能找到处理入口。正文原地呈现 HTML；不自动跳到外部阅读器，不把纯文本作为 HTML 的替代品。

中文界面先行；产品名暂沿用仓库的 **Maild**，不额外改品牌。系统 UI 字体配合 PingFang SC，避免下载字体和无意义的常驻动画。默认舒适密度，提供紧凑密度；两者共用信息架构。

默认前端通过插件包分发是安装与替换机制，不应该成为读信过程中的操作步骤。首次启动直接进入邮箱或账户向导，不要求用户先理解 daemon、RPC、capability 或插件。

### 参考与独立设计声明

2026-09-11 查阅以下第一方资料，只提取交互原则，没有复制 Pebble 或其他客户端源代码、样式、图标或素材。

| 参考 | 观察 | Maild 采用与舍弃 |
|---|---|---|
| [Thunderbird Quick Filter](https://support.mozilla.org/en-US/kb/quick-filter-toolbar) | 未读、星标、附件等快速过滤靠近列表 | 采用列表局部筛选；复杂查询用可见字段，不要求记搜索语法 |
| [Mailspring](https://www.getmailspring.com/) | 统一收件箱、多账户搜索、主题和键盘操作 | 采用统一入口与账户身份提示；不引入跟踪、提醒、CRM 等本阶段外功能 |
| [Pebble README](https://github.com/QingJ01/Pebble) | 本地优先、逐封隐私控制、HTML 样式与批量操作 | 采用可见的远程资源控制；不引入看板、壁纸、翻译和 WebDAV 功能 |

没有对参考客户端做资源占用基准测试。Tauri 与 egui 的实际占用差异应在实现后测量，不能沿用“必然严格更轻/更重”的断言。

## 确认方式

主界面总体方向已获用户认可。本次进一步确认 [界面扩展](UI-EXTENSIONS.md)：原位增加功能、工作页及可分离窗口，同时保留普通邮箱的默认阅读体验。用户确认这份设计后，才能把相应部分标为已接受并开始 M4.5-03 的正式前端实现。UI 原型不是实现完成证明，也不自动批准新增内核能力。
