# 视觉规范：纸面阅读工作台

评审稿 v1.1。适用默认 Tauri 前端，独立于其 React/Vue 等实现选择。

## 1. 氛围与识别

三个关键词：**安静、明确、耐读**。墨绿色只用于主要动作、选中位置和状态点；正文自身的色彩与版式不被应用品牌覆盖。外壳以底色层级分区，不把每封邮件和每个设置项都装进卡片。

视觉锚点是右侧真实排版的邮件和左上角克制的 Maild 字标。没有营销式欢迎横幅、装饰渐变、壁纸、玻璃模糊或悬浮 AI 按钮。原型中的刊物文字与排版均为本项目创作的虚构内容。

## 2. 颜色与语义

原型唯一样式策略为普通 CSS + 命名 CSS variables，无 UI 框架、无外部资源依赖。正式实现可将相同 token 落到 CSS Modules，不能同时引入两套组件样式系统。

| Token | 浅色 OKLCH | 深色 OKLCH | 用途 |
|---|---|---|---|
| `--sidebar` | `94% .008 155` | `19% .008 155` | 账户与文件夹，低于正文亮度 |
| `--canvas` | `97% .004 155` | `16% .006 155` | 列表与空工作区 |
| `--surface` | `100% 0 0` | `22% .008 155` | 阅读外壳、输入区域 |
| `--ink` | `26% .018 155` | `92% .008 155` | 主文字 |
| `--muted` | `48% .015 155` | `72% .012 155` | 次文字、元数据 |
| `--accent` | `43% .085 165` | `77% .08 165` | 主按钮、焦点、链接 |
| `--selected` | `91% .035 165` | `30% .04 165` | 选中项，另有字重与标记辅助 |
| `--line` | `89% .009 155` | `33% .012 155` | 分栏线、表单线 |
| `--warning` | `47% .09 65` | `81% .09 65` | 等待用户处理、不确定结果 |
| `--danger` | `47% .15 28` | `78% .10 28` | 明确失败、破坏性动作 |

状态必须带文字或图形，不依赖颜色区分。目标是 WCAG 2.2 AA，常规文字 ≥4.5:1、关键控件/焦点 ≥3:1；正式实现按最终字体与实际合成色复测。评审原型的透明覆盖层不能用于降低重要文字的对比度。

## 3. 排印

系统 UI 字体 `-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`。这是桌面工具的有意选择：不引入字体下载，匹配 macOS 操作环境，中文和拉丁文的字重都有可用实现。

| 层级 | 字号 / 行高 | 字重 | 用途 |
|---|---|---|---|
| 产品字标 | 22 / 28 | 650 | Maild |
| 页面标题 | 24 / 32 | 650 | 设置、账户向导 |
| 邮件主题 | 22 / 31 | 600 | 阅读区标题，允许多行 |
| 列表主行 | 13 / 20 | 未读 650；已读 450 | 发件人 |
| 列表主题 | 13 / 20 | 未读 600；已读 400 | 一行省略 |
| 辅助信息 | 12 / 18 | 400 | 时间、来源、摘要 |
| 应用正文 | 14 / 23 | 400 | 设置与错误解释 |
| 写信正文 | 15 / 26 | 400 | 原窗口编辑区 |
| 纯文本邮件 | 16 / 27 | 400 | 本来只有纯文本的信，不是 HTML 降级替代 |

数字使用 tabular-nums。正文 HTML 保持发件人排版，应用不把自己的字体、dark CSS 或行高强塞进去；不可用的远程字体回退系统字体。禁止通过缩小中文按钮文字解决空间问题，优先收起次要动作。

## 4. 控件与状态

- 间距刻度：4 / 8 / 12 / 16 / 24 / 32 / 48px。控件圆角 6px，选中行 8px，浮层 12px；整页不加额外圆角边框。
- 导航行 40px 高；列表舒适 90px，紧凑 68px。图标可见尺寸 18px，按钮命中区 ≥40×40px，触摸 ≥44px。
- 主按钮填墨绿，同一区域只设一个主动作；次按钮浅底，危险动作在语义明确时用危险色。
- 悬停改变底色；按下只做 `scale(.98)`；焦点外环 2px；禁用不可只降低透明度，必要时就地说明原因。
- 输入框有持久标签、可见边界；placeholder 仅举例。错误与对应字段邻接，不能只给一个全局 toast。
- 通知 toast 放工作区底部，不遮发送按钮。只用于已完成或可继续的操作；需要用户裁决的问题留在同步活动里。
- 复选框与行选择独立。鼠标/键盘都能进入批量操作，主行负责预览；选中数量替换列表工具栏，不弹确认框争夺阅读区。
- 列表行中的星标不是按钮套按钮，使用独立兄弟控件。

## 5. 布局

桌面推荐窗口 1440×900，最低可用产品窗口候选 900×640，最终由真机验收确认。原型为方便跨设备评审额外适配到 375px，**不代表本阶段交付手机端**。

| 空间 | 默认值 | 约束 |
|---|---|---|
| 导航栏 | 216px | 正式版拖动 184–272px，可折叠 |
| 列表栏 | 344px | 正式版拖动 280–460px；优先保阅读宽度 |
| 阅读区 | 剩余宽度 | 阅读内容最大 760px，居中但主题/工具栏同边界 |
| 顶栏 | 64px | 列表搜索与阅读动作各归属本栏 |
| 设置内容 | 最大 800px | 长页独立滚动，分组标题与行对齐 |
| 浮层 | 最大 560px | 只用于需明确决策的动作，如丢弃草稿、未知结果重试 |

邮件列表、正文、设置分别滚动；外壳本身不滚。选中邮件后列表位置不跳，切账户/文件夹记住本次会话内选择与滚动位置。超宽 HTML 表格在**邮件内**水平滚动，不撑开外壳，也不把整封邮件缩成不可读的小字。

## 6. 深度

侧栏灰绿、列表近白、阅读白，配 1px 分隔线。阴影只用于 modal、菜单和 toast，常规设置用分组行。深色模式靠亮度阶梯表达层级，不靠黑色阴影。

HTML 原文默认保留自己的浅色画布，即使外壳深色也是如此；阅读工具提供「原色 / 适配深色」选择，适配模式属于单独的实验能力，当前设计默认不启用。原型深色截图展示“深色外壳 + 原色邮件”，这是有意取舍。

## 7. 行为约束

1. HTML 默认原位读，无需“打开原文”才能得到正常邮件体验。
2. 用户看到邮箱名称、显示名和地址，不看到数据库 ID、manifest、token 或原始异常栈。
3. 邮件操作与线程范围分明。工具栏默认只作用于当前选中的邮件，不无声处理整条跨文件夹会话。
4. 不承诺当前内核没有的撤销、自动保存、附件下载、离线发送和 OAuth。
5. 同步成功不 toast；持续异常可见，且明确受影响账户。
6. 不在发信已确认成功后提供“再发一次”，已发送副本同步失败单独处理。
7. 用户数据不用于原型；不请求真实登录；不把任何 UI mock 标成生产验证。
8. 原生关闭/最小化/全屏使用平台窗口按钮；原型圆点只表示窗口装饰，不伪装可操作控件。

## 8. 响应式与无障碍

- ≥1200px：完整三栏。
- 900–1199px：导航收为窄轨，列表 310px；完整文件夹树由可关闭抽屉打开。
- 600–899px：列表与阅读两栏，导航为抽屉，阅读最小 320px。
- <600px：列表/正文一次显示一层，阅读顶部必有“返回列表”；写信保持同窗口整页。
- 200% 缩放按有效宽度降级。屏幕阅读器使用 navigation、main、region、heading；图标按钮有可读名称，列表当前选择使用 `aria-current`。
- `prefers-reduced-motion` 关闭入场位移；常规动画 120–160ms，只作用 opacity/transform，不持续旋转同步图标。
- modal 锁焦点，关闭恢复触发控件；抽屉有返回/关闭；错误用 alert，成功用 polite live region。

## 9. 后续实现指令

实现列表：使用 sidebar/canvas/surface 三层底色；344px 列表，90px 舒适行；发件人、主题、摘要、时间、附件与未读状态各自独立，不额外加卡片阴影。

实现阅读：主题与收件人信息在可信 UI；正文在隔离容器；墨绿动作属于可信外壳；邮件原文拥有独立样式与滚动边界；详情过期时不能把上一封内容留给新选中项。

实现设置：最大 800px 的单列分组行；运行时设置明确写“应用到本次运行”；只有持久化已完成才用“已保存”；连接错误必须保留可操作的账户入口。

生产框架、组件库和状态桥接方案在设计通过后由 M4.5-03 ADR 选择。本设计不以原型 JavaScript 的实现方式约束产品架构。

## 10. 插件界面扩展补充

主界面总体方向已获认可。默认邮件功能按模块注册，第三方扩展能贡献动作、面板、工作页与窗口；位置和状态遵守 [UI-EXTENSIONS.md](UI-EXTENSIONS.md)。1360px 以上的阅读区可并排 300px 扩展侧栏，较窄宽度使用阅读区内单层切换。扩展标题栏显示来源，主题 token 可向隔离视图提供，但插件 CSS 不污染宿主或邮件文档。
