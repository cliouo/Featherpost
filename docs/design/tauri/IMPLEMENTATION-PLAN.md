下表第 2 节「授权缺口」一行已闭合，`permissions` 声明模型、四个受托管理词与负向矩阵都已落地。

`crates/maild-ui`（Tauri 2 壳、`frontend:com.maild.ui` 身份、桥的 DTO/错误投影）与

检查位置：`crates/maild/src/api.rs` 的 `method_policy`（本次基线 568 行起），[协议](../../protocol/README.md)、[ADR-0024](../../decisions/0024-builtin-frontend-tauri-migration.md)、[ADR-0027](../../decisions/0027-mailbox-write-path-and-offline-queue.md)、[ADR-0028](../../decisions/0028-compose-reply-and-sent-append.md)。

| 用户能力 | 当前事实 | UI 交付依赖 |
|---|---|---|
| 账户/文件夹/摘要/正文读取 | 内核 API 已有，messages_read 可用 | 03 的 Rust 桥接与分页 |
| HTML 原文 | 04 后在 sandbox iframe 里原位渲染，截断与「此缓存中没有 HTML 版式」有注记 | ✅ 已闭合；「适配深色」模式仍是独立实验能力 |
| CID 与附件下载 | G02 字节通道 + 04 的令牌资源通道与系统保存面板 | ✅ 已闭合 |
| 标记/归档/删除/队列 | 内核已实现；G01 后归 `mailbox_write`，前端声明即可调用 | ✅ 08-B 已接入批量写回、精确回执和失败/未知恢复 |
| 回复/账户发信 | G01 后 `prepareReply` 归 `messages_read`（纯读）、`sendFromAccount` 归 `messages_send` | ✅ 授权已闭合；仍不可绕过内核重新拼回复头 |
| 账户中心/地址/扩展管理 | G01 后分别归 `accounts_manage` / `addresses_manage` / `plugins_manage`，三词仅前端可声明 | ✅ 08-C 已接入；安装与回滚均显示版本和将获授权，安装附来源 |
| 本地搜索/线程 | messages_read 可用；线程消息正序 | ✅ 08-B 已接入本地筛选、索引覆盖、跨文件夹会话与分页 |
| 服务器搜索后阅读 | server SEARCH 只给摘要，不落库 | 未补下载契约前不提供假阅读按钮 |
| 草稿保存 | G03 后是 daemon 拥有的持久状态，版本化更新、重启可恢复 | ✅ 08-A 已接入编辑器、防抖保存、冲突恢复与关窗保护 |
| 新文件附件上传 | G04 的主体绑定分块上传、版本化完成与草稿字节持久化 | ✅ 08-A 已接入原生选择/拖入、进度、取消、重试与移除 |
| 远程图片信任名单 | G02 的内核策略 + 04 的拦截、横幅与「阅读与隐私」分区 | ✅ 已闭合 |
| 日用通知/规则 | 通知授权请求 G01 后归 `settings_write`；规则仍是 runtime-only | 08；**不得承诺规则持久化** |
| 前端 UI 偏好 | 不是邮箱领域数据；存储边界需明确 | 03；只保存非敏感偏好 |
| 删除 egui 后恢复 | ADR-0039 已取代保留 egui 的决定；09-A/B/C 已完成，egui 已删除 | 10 发布门禁实跑签名与图形激活 |

**原结论：现有 frontend capability 路由不能完整承载日用主路径。** 不能“为了能用”把 user bearer 暴露给 webview，不能只给内置包放行而保留“没有特权”的文档。

**G01 的处理方式**（[ADR-0030](../../decisions/0030-frontend-authorization-closure.md)，已同步
ADR-0018/0024）：不新增「受限 user 中介」这一层，而是把 manifest 的 intent 路由与纯授权拆成
两个字段，并补齐词表到日用主路径够用。webview 侧仍然永不接触 bearer——03-A 的宿主用 Rust 持
认证连接，JS 只调类型化 command。**并如实记录：daemon 侧这条上限是自愿声明而非沙箱**，它挡
的是宿主扩展代理层的 bug 与权限蔓延（E02 的 host ↔ extension 才是可强制的那条边界）。

## 3. 设计冻结检查点

| 编号 | 用户确认内容 | 可查看材料 | 通过标准 |
|---|---|---|---|
| D01 | 视觉方向、密度、栏宽与暗色外壳 | 原型收件箱/主题/紧凑模式 | 连续阅读时字体与信息量舒适 |
| D02 | 同窗口阅读/回复/写信/返回 | 原型会话与草稿 | 不弹额外 reader，不丢草稿上下文 |
| D03 | 搜索/多账户/设置信息架构 | 原型搜索与七组设置 | 用户能找到日常动作，不依赖 CLI |
| D04 | 离线/认证失败/结果未知 | 评审情景选择器 | 能分清已发送、待同步、未确认 |
| D05 | 补齐草稿/附件和替代 egui 恢复 | 本文 G01–G05 | 接受扩大的交付范围及顺序 |
| D06 | 界面扩展点、默认模块化、独立窗口 | [扩展设计](UI-EXTENSIONS.md) 与摘录示例 | 入口可增减、面板可分离/收回、权限和生命周期清楚 |

用户的“总体问题不大”认可了主界面总体方向；尚不视为全部工程方案或新增扩展设计均已批准。设计修改以用户反馈逐项修订，不默默替换整个风格。
