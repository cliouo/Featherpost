# 默认前端交互规范

评审稿 v1.1，2026-09-11。用户已认可原型并授权按计划实现；外部界面扩展与窗口仍按 E02/E03 单独验收。本文作为前端行为基线；未交付能力均见 [实现清单](IMPLEMENTATION-PLAN.md)。

## 1. 产品目标与优先级

为用户自己的 Mac 提供能长期使用的普通邮箱客户端。优先顺序：正确读 HTML → 正确回复与发送 → 多账户整理 → 找回邮件 → 清楚处理失败。界面扩展底座在 03 阶段就设计并采用；具体高级业务插件在日用后再评估。插件可贡献菜单、局部面板、工作页和独立窗口，默认不挤占邮件主导航，详见 [界面扩展设计](UI-EXTENSIONS.md)。

成功条件：不用 CLI 即可添加受支持账户、阅读 HTML、回复、管理文件夹内的邮件、搜索、诊断账户错误。可替换前端是系统能力，不成为用户每次阅读必须理解的概念。

**设计时基线**：01/02/05/06/07 已有仓库实现。当前 Tauri 已完成 03-A/E01、04、08-A/B/C，详见 [交付计划](IMPLEMENTATION-PLAN.md)；本规格还包含后续 E02/E03/09/10 的目标，不把设计覆盖当作已发布能力。

## 2. 信息架构

```text
Maild
├─ 邮件工作区（默认入口）
│  ├─ 全部账户：收件箱 / 星标 / 草稿 / 已发送 / 归档 / 废纸篓
│  ├─ 每个账户：服务器文件夹树 / 垃圾邮件 / 自定义文件夹
│  ├─ 列表：搜索 / 未读过滤 / 密度 / 批量选择
│  └─ 阅读：HTML / 收件人详情 / 会话历史 / 附件 / 内联回复
├─ 写邮件（原窗口）
│  └─ 发件账户与别名 / To / Cc / Bcc / 主题 / 正文 / 附件 / 草稿
├─ 搜索（复用列表和阅读区）
│  └─ 关键词 / 账户 / 文件夹 / 发件人 / 时间 / 附件 / 搜索覆盖状态
├─ 设置（原窗口，始终可返回邮件）
│  ├─ 账户：添加 / 探测 / 编辑 / 凭据更新 / 启停 / 移除
│  ├─ 外观与操作：主题 / 密度 / 快捷键 / 窗口行为
│  ├─ 阅读与隐私：HTML 显示 / 远程资源 / 可信发件人 / 链接
│  ├─ 通知与规则：系统权限 / 预览 / 账户规则 / 静默时段
│  ├─ 地址与别名：能力感知 / 创建 / 启停 / 移除
│  ├─ 扩展：已安装 / 默认前端 / UI 贡献 / 权限 / 安装 / 升级 / 回滚

└─ 首次使用 / 连接修复 / 前端修复入口
```

不设置“仪表盘”主页、看板、AI、翻译、日历、CRM、阅读跟踪或扩展市场入口。用户启用的扩展可以增加自己的工作页与窗口，并通过宿主提供的展示入口使用；默认收件箱顺序由用户控制。

## 3. 主窗口与列表

### 3.1 账户与文件夹

首次有账户时打开统一收件箱；08-B 在当前进程内保留范围与搜索前的位置，重启后回到统一收件箱。邮箱名称与邮件身份不写浏览器持久存储。统一只聚合 inbox role，不把 spam/trash/sent 混入新邮件。每条摘要保留完整 `(account, folder, uid)`；所有操作带原始 folder 身份，显示用解码后的名称。

账户显示名优先，次行真实地址；没有名称时回退地址，最后才是稳定 ID。统一列表用来源标识辅助区分，发信始终显式选择账户和别名。账户颜色仅为辅助，不代替文字。

文件夹折叠状态与栏宽是前端偏好，存放位置需遵守无敏感元数据自有存储约束。不可写死 INBOX/Sent/Trash 为远程命令目标。无特殊文件夹映射时说明原因；归档目标由用户选择，删除需说明是否只能标记删除。

### 3.2 列表信息

发件人、主题、摘要、时间、未读点/字重、星标和附件提示。舒适行 90px、紧凑行 68px；主题和发件人省略但支持可访问完整名称。日期按本地时区显示，悬停/详情显示完整年月日与时区。

时间排序遵循内核 `sort_at`，不重新按显示字符串或到达 UI 的先后排序。对异常 Date，详情区可同时显示发件人声明时间和收信观测时间，避免把排序时间误写成原始 Date。

本期列表基本单位是**邮件**；详情可展开整个会话。08-B 会话摘要每页 30 条，当前窗口最多 1000 条；续页发现总数变化要求重新展开，防止偏移错位。线程 ID 为 0 或尚未回填时显示单封邮件，不显示假的“1 封完整会话”。同主题不同 Message-ID 不自动合并。线程聚合列表需要跨分页稳定分组，不能用当前页 JS 去重代替全局语义，因此列为后续独立实现选择。

### 3.3 选择与多选

单击主行预览，复选框进入批量模式；Shift 可选连续范围，⌘/Ctrl 可选择不连续项。批量工具栏显示明确数量，默认不选中当前分页以外的邮件。“全选当前加载”与“选择全部结果”不能混用，后者没有契约时不提供。

批量操作按账户/文件夹拆请求，每次最多 500 UID；部分成功显示“7 封已排队，2 封未确认”，失败项保留选择；已经满足标记状态的邮件独立计数，不误报失败。不同账户不提供单次跨账户移动。一次点击不会无声处理跨文件夹的整条会话。

08-B 保留手动标为已读，打开邮件本身不写回。800ms 自动已读仍是独立待定的产品选择，不能把原型暗示当作已实现行为。

## 4. 正文阅读与 HTML

标题、发件人、收件人、动作处于可信 UI；邮件 HTML 位于同窗口的隔离文档。切信立即清除上一封敏感内容，显示当前主题与正文加载态。旧请求返回不得覆盖新选中的邮件。

- HTML 有且可用时默认渲染 HTML；不提供必须额外打开窗口的“高清模式”。
- 只有邮件自身无 HTML 时才显示纯文本。历史缓存缺少 HTML 时明确“此缓存未保存 HTML”，提供重新同步说明；不能伪称原邮件只有文本。
- `cid:` 图片属于本封附件资源；原文中远程图片、远程样式和网络字体默认不联网。保留可安全使用的内联 CSS 和布局。
- 信任白名单只接受明确发件人，不把单封“加载图片”升级为永久信任。名单管理位于设置；首次添加说明会请求远程资源。
- 深色外壳默认保持邮件原色。不使用全局 invert，也不把白底营销邮件强行染成深色。
- 链接能查看实际目标，允许的 http/https 交系统浏览器；mailto 在当前应用发起写信；其他协议必须明确分类，不静默执行。
- 邮件网页表单不能提交，脚本和应用 IPC 不可执行。真实拦截能力需 WKWebView 验收；原型的 sandbox fixture 不证明完整隔离方案。
- 超宽表格邮件内部横滚，长邮件内部纵向可读；不缩小字体适配整封固定宽版式。正文高度管理须避免双重纵滚，原型固定 iframe 高度只是评审近似。
- HTML 截断标记出现时提示“此缓存中的正文不完整”，重新取回完整原文需独立能力；不能把已有 256KiB 上限误当完整支持。

附件排在对应那封信后面，显示文件名、类型、大小和可用状态。附件字节不可用时显示“尚未保存此附件”，不制造可成功下载的按钮。保存时用系统文件选择，重名由用户处理，失败不删除已有目标。CID 图不重复列为普通附件。

## 5. 会话与回复

默认展开当前邮件，之前来往收为一条摘要，标明封数。展开后按时间正序，每封保留来源账户/文件夹；最新未读定位不导致历史滚动跳动。

回复/全部回复在当前邮件下方展开。From 默认原来收信账户，别名匹配由内核确定；收件人通过 `prepareReply` 返回，前端不自行拼接 References。全部回复明确展示新增的收件人，自己的地址和别名不重复加入。

编辑回复可收起后继续阅读，草稿关联**原邮件身份 + 回复模式**，切换邮件后不能串用。转发在原窗口编辑页打开新的邮件，清除继承会话头；带回可读的已有附件引用，不能静默丢附件。

## 6. 写信与发送

新邮件占原窗口工作区，保留侧栏；正文不弹另一个 OS 窗口。字段按 From、To、折叠 Cc/Bcc、Subject、Body 排列。界面支持多个地址，地址 chip 可删除/编辑；长地址换行而不撑宽窗口。原型用文本地址框代表最终 chip 输入。

写信本期保持纯文本编辑，HTML **阅读**不受影响。Markdown→HTML 仅在序列化/预览方案明确后启用，不展示虚假的富文本工具栏。

校验顺序：发件身份可用 → 收件人非空/逐项合法 → 字段字节上限 → 附件全部准备完成 → 无主题/提到附件却未添加时提醒。校验失败焦点移到第一个错误，保留全部内容。客户端校验不替代服务端防头注入。

### 发送状态

| 状态 | 可见反馈 | 可用动作 | 禁止行为 |
|---|---|---|---|
| 编辑中 | 草稿状态、收件人与正文 | 继续编辑 / 保留草稿 / 发送 | 无持久化时显示“已保存” |
| 正在发送 | 按钮“正在发送”，字段冻结 | 保持当前编辑上下文 | 连点重复发、超时自动再发 |
| 明确失败 | 具体原因与保留内容 | 修改 / 主动重试 | 清空正文、误写已发送 |
| 结果未知 | “投递结果尚未确认” | 核对已发送/收件人，保留内容 | 自动重发或普通重试按钮 |
| 已投递 | “邮件已发送” | 返回阅读 / 查看已发送 | 因 APPEND 失败显示投递失败 |
| 已投递，副本同步异常 | “邮件已发送，副本同步需要处理” | 查看同步活动 | 鼓励重新发送正文 |

普通的“撤回发送”或“撤销发送”本期不显示，没有服务端撤回契约。若未来做延迟提交，必须明确 SMTP 尚未执行，不把已投递事实包装成可撤销。

### 草稿与附件的产品缺口

日用目标需要可靠的本地草稿：后台拥有存储，编辑后 500ms 防抖提交；只有 daemon 持久提交回执后才能显示“已保存”，关闭窗口需等待最后一次保存结果；失败保留编辑器并提供重试/复制内容。退出后恢复多份草稿是验收项。服务器 Drafts 同步另行决定，不承诺已跨设备保存。

**草稿的后台一侧已由 M4.5-G03 交付**（[ADR-0034](../../decisions/0034-daemon-owned-drafts.md)）：草稿是 daemon 拥有的持久状态，`updateDraft` 的回执是“已保存”的唯一来源，过期的 `base_version` 被拒绝而不是合并，超限拒绝而不截断，服务器 Drafts 同步是明确的非目标。**08-A 已实现**编辑器、500ms 防抖、关窗/⌘Q 等待保存、冲突保留输入与复制内容；见 [ADR-0036](../../decisions/0036-compose-workspace-and-durable-send.md)。回复按原邮件身份与模式隔离，新建/转发在原窗口工作区，回复在阅读区内展开。

发送以已保存的草稿版本为准，发送中冻结字段；明确失败允许修改后主动重试，结果未知只提供刷新、核对后解锁或显式丢弃。成功先记录已投递，再显示副本是否已加入同步队列；入队不等于服务器已归档。新编辑器当前提供纯文本正文，HTML 阅读保持原版式；已有 HTML 草稿须明确转换后才能编辑，不静默丢弃 HTML。

新附件目标流程：选文件/拖入 → 每个附件显示准备状态 → 准备完成可发送 → 可取消、移除、重试 → 失败定位到该文件。大小限制由实际 staging 契约提供，不在设计里拍定 25MB 等服务商额度。空文件、多字节长文件名、路径穿越、同名附件分别验收。**G04 + 08-A 已接入**：Rust 原生选择/拖入、512 KiB 分块、20 MiB 单文件上限、进度/取消/重试；路径与文件字节不进入 JS。原生拖入仅作用于当前可见的可编辑草稿。

原型的暂存只在页面内存，刷新清除；新附件按钮显示设计说明，不伪造上传完成。

## 7. 搜索

⌘K 搜全部本地邮件；输入关键词按 Enter 开始，输入框保留关键词。结构化筛选提供账户、文件夹、发件人、时间范围、有附件，每个条件都可移除。用户输入 `from:xxx` 时不宣传 Gmail 查询语法，内核将其当文字。

默认时间倒序，与普通列表一致。搜索不新开工作台，结果可原位阅读、回复与标记；退出搜索恢复之前文件夹位置。返回的“总数”与已加载数分开，结果按页加载，当前窗口最多保留 1000 条摘要，超出提示用筛选缩小范围；不提供未实现的“选择全部结果”。

`getSearchIndexStatus.pending > 0`：非模态提示“正在建立索引，结果尚未完整”，不画假百分比。无结果时先提供清除筛选，再提供改关键词。

服务器搜索是明确的二级入口：选一个账户与文件夹，要求在线、关键词非空；展示“服务器结果，最多 200 条”。当前 server 结果仅摘要、不落库、不能直接 `getMessage` 读信。设计在结果旁标“正文未下载”，不可给可阅读假象；下载入库能力未补齐前，不把此入口作为日用搜索救济承诺。原型只覆盖本地搜索。

## 8. 离线与同步活动

要区分三个边界：邮箱服务器离线但 daemon 可用；daemon 连接不可用；版本不兼容。只有第一种能继续安全提交本地排队修改。后两种显示缓存并禁写，不能宣称改动已排队。

| 场景 | 文案 | 后续 |
|---|---|---|
| 正常同步 | 侧栏“所有邮箱已同步” | 不打断 |
| 有离线操作 | “3 项操作待同步” | 点开按账户、动作与邮件列出 |
| 单账户离线 | “工作邮箱离线” | 自动重连；可读缓存，保留草稿 |
| 认证失效 | “工作邮箱需要重新登录” | 图形凭据更新，其他账户继续 |
| IMAP 明确拒绝 | “归档失败：目标文件夹不存在” | 选其他目标 / 主动重试 |
| move/append unknown | “结果未知，请检查目标文件夹” | 查看目标 / 有风险说明的重试 / 不再重试 |
| 源信消失、目标尚未同步 | “已排队，目标文件夹同步中” | 不声称邮件丢失，不造目标 UID |
| 不认识的新状态 | “此版本无法处理该操作状态” | 保留摘要，建议更新；不当成功或失败 |

unknown 的“不再重试”不叫“撤销”；归档/删除 toast 不提供当前契约无法保证的撤销按钮。检查目标文件夹不等于自动判定成功，`discard` 只停止要求重放。

活动页要读取 settled 失败项，不能仅使用 `listPendingOps` 默认过滤，否则 failed 会消失。队列底层 payload 可能包含邮件，不直接作为日志或诊断文本显示。08-B 使用带权限校验的摘要通道，源邮件主题最多 512 字符；APPEND 原文不参与摘要读取，服务端错误原文映射为受控文案。活动页可见时每 5 秒刷新，加载历史后暂停自动刷新以保留位置。

## 9. 首次使用与账户管理

首次运行不创建 Maild 云账户：选择 IMAP/SMTP 或已经安装的服务扩展 → 输入地址、显示名、主机、端口、TLS、认证资料 → 分别探测收信/发信 → 确认连接 → 首轮同步 → 进入收件箱。OAuth 与不支持的提供方不展示可点击的一键登录。

探测失败停留在表单，保留非秘密字段，错误按接收/发送分列；认证字段只在输入提交链中使用，不回填、记录到日志或保存到前端 localStorage。TLS 失败不通过自动关闭证书验证绕过。

NodeSeek 等扩展账户需只读探测已有邮箱后绑定；创建远程新邮箱须独立确认，不放在探测或“下一步”副作用中。扩展被停用/缺失时显示依赖并给恢复入口。

账户中心提供：启停、探测、更新凭据、修改显示名、别名、移除。删除确认显示准确账户、待提交操作、影响本地缓存/凭据与服务器的范围。使用现有 removeAccount 的真实参数和结果；不能替用户新增“删除服务器所有邮件”选项。

08-C 已接入上述管理流程。收信与发信可分别使用 IMAP/SMTP 或插件，编辑一侧不会重置另一侧；
已有密码不回填，保存或放弃后清空本次输入。探测成功绑定当前表单，修改输入后需重新探测。
离开设置、切分区或关闭窗口遇到未保存输入先确认；关闭获准后到草稿保存完成期间锁定设置。
通知导航等待确认后再定位完整邮件身份，不能先在后台定位后把目标丢掉。

## 10. 设置、地址与扩展

- 设置入口固定侧栏底部，⌘, 直达。账户配置常驻可用，不能只提供 CLI。
- 通知权限在用户愿意开启通知时请求；首次阅读前不连续弹系统权限框。拒绝后给系统设置指引。
- rules 当前是运行时-only。成功写“已应用到本次运行”，dirty 返回需确认，静默时段显示固定 UTC 偏移，不能宣传自动夏令时处理。
- 地址与别名依据 provider 能力决定创建、读取和停用按钮。08-C 的登记是本地发件身份，不会创建远程邮箱；SMTP 用户需确认服务商已支持，当前插件主地址模式不提供可发别名创建。Compose 的 From 只显示 active 可发地址，停用后不能沿用旧选择发送。
- 扩展页先展示已安装、默认前端和账户依赖。08-C 使用原生目录选择、staging 副本与单次安装令牌，回滚也先确认权限；依赖账户无法读取时明确提示未知。刷新会重新扫描受管目录。安装/升级流程先校验包，再显示来源、版本、权限与影响，执行完成反馈原子事务结果；失败显示是否回滚成功。
- 前端切换先校验包可启动，再生效；默认前端被删除或损坏，要有图形修复路径。普通用户不进入 manifest 编辑器。
- 备份/恢复不能写成低风险即时开关。现有维护锁、停止 daemon、候选校验和回滚记录按运营契约设计独立向导，本轮设置页先提供说明入口。

### 10.1 界面贡献与扩展窗口

插件既可替换完整前端，也可贡献默认前端里的动作、侧栏、工作页和独立窗口。默认邮件模块也用同一注册/销毁机制。具体贡献点、授权范围、窗口单实例、分离/收回、停用/升级/退出与资源预算见 [UI-EXTENSIONS.md](UI-EXTENSIONS.md)。这些是新增设计，不是既有 `ui_executable` 原生管理界面接口。

## 11. 窗口、激活、Dock 与菜单栏生命周期（已冻结契约：ADR-0044 / 0045 / 0046）

通知点击、Dock 再次打开、顶部菜单栏 `✉`、`OpenIntent`、mailto 都定位**同一个主窗口**（由 `.main-ui.lock` 保证单实例，全程 Dock 最多只有一个 `Maild` 图标，绝不出现第二个 `Maild UI` 图标）。阅读激活如果遇到未保存草稿，先可靠暂存，再定位到邮件；发送状态未知时不得无提示覆盖编辑区。新消息意图携带 account/folder/uid；缺少 folder 的旧通知只打开账户列表，不猜 UID。导航代次从等待草稿保存之前开始，后续手动导航优先。普通新邮件通知刷新列表，保留当前正文与阅读位置。

macOS 窗口与后台生命周期严格区分「暂存窗口」「关闭前端退回菜单栏」与「彻底退出整个应用」三类意图：

1. **黄灯最小化（`–` / `⌘M` / 双击标题栏）＝ 暂存窗口（原生最小化）**：保持 100% macOS 原生 `performMiniaturize:` 行为，保留 Dock 上的 `Maild` 图标以及下载与废纸篓之间的窗口缩略图，不劫持黄灯按钮或快捷键；用户可随时点击缩略图、Dock 图标或菜单栏还原继续写信/读信。
2. **红叉关闭（`×`）/ 快捷键退出（`⌘Q`）/ Dock 右键图标点「退出」＝ 仅关闭前端窗口并彻底清空 Dock**：三条路径统一收敛到同一条优雅关闭流水线——遇到上传中、发送中或未保存设置确认时允许前端否决保留窗口；获准关闭后刷盘草稿，在主线程隐藏窗口（含收走最小化缩略图）并切回 `Accessory` 提交给 WindowServer，随后退出 `maild-ui` 释放全部 WebView 内存。配合顶层 `Maild.app` 的 `LSUIElement = true`，退出后 **Dock 栏零活动图标、零「最近使用」残留、零「Maild 正在后台运行」幽灵图标**，仅顶部菜单栏保留 `✉` 与极低占用后台收信守护。系统注销/重启/关机时同步降级并直接放行，绝不阻断系统注销。
3. **顶部菜单栏 `✉` 与后台生命周期强绑定（「退出 Maild」＝ 全栈彻底退出）**：只要后台守护在运行，顶部菜单栏 `✉` 就始终常驻（不提供仅关闭菜单栏却把后台孤立留下的「退出菜单栏」选项）。菜单最后一项固定为 **「退出 Maild」**，点击后触发 `stopManagedAgent` 并向在线前端推送 `agent/stopping`（500 ms 宽限兜底），让正在打开或最小化的前端窗口、Dock 图标、顶部菜单栏 `✉`、外部插件与后台收信守护一并干净退出。
4. **独立原生修复入口（[ADR-0039](../../decisions/0039-native-recovery-and-tauri-default.md)）**：旧 egui 已彻底移除。默认 Tauri 前端自身损坏或缺失时，由独立的最小系统原生修复界面承接查看后台状态、离线/在线一键恢复内置默认前端包与错误诊断；主窗口在线时伴随打开的修复弹窗以 `Accessory` 身份浮动显示，不新增第二个 Dock 图标。

## 12. 键盘与辅助技术

| 快捷键 | 作用 | 条件 |
|---|---|---|
| ⌘K / Ctrl+K | 搜索本地邮件 | 保留当前编辑内容 |
| ⌘N / Ctrl+N | 新邮件 | 有现存草稿时先暂存，不覆盖 |
| ⌘R / Ctrl+R | 回复 | 产品内选中可回复邮件，浏览器原型不劫持刷新 |
| ⌘⇧R / Ctrl+Shift+R | 全部回复 | 产品内支持，原型用按钮 |
| ⌘Enter / Ctrl+Enter | 发送当前草稿 | 先校验，锁重复提交 |
| ⌘, / Ctrl+, | 设置 | 原生菜单也提供 |
| ↑ / ↓ | 上一封 / 下一封 | 列表获得焦点，编辑与正文选区不劫持 |
| Space | 选择/取消当前行 | 多选模式，普通阅读保留滚动 |
| Escape | 关闭最顶层浮层；再返回列表 | 草稿关闭必须保存或确认 |

正式产品提供可见菜单路径，快捷键不是唯一入口。屏幕阅读器朗读未读/星标/选中与发件人，不强制连续播报后台刷新。焦点不会随新邮件到达跳走。

## 14. 性能与隐私目标

只为当前邮件实例化 HTML 阅读上下文；隐藏历史正文按需创建/销毁。列表虚拟化、摘要和正文按需获取，长信不能拖住导航。前端退出后不保留为了动效而存在的定时器。

无远程字体、外壳图片 CDN、遥测和默认网络加载。明确区分本地渲染测试、真实 IMAP/SMTP、WKWebView 权限隔离与发布包验收。资源数字只能来自指定设备、账户数量、邮件 fixture 和前后台状态下的测量，不从技术栈名称推断。
