# ADR-0006：M3 rules 设置使用基线草稿与显式运行时应用

- 状态：Accepted
- 日期：2026-08-20
- 适用范围：M3 桌面 rules 设置体验

## 背景

JSON-RPC v1 已提供 `getSettings` / `setSettings`，当前只允许读取和部分更新 rules。修改会
立即影响通知路由，但不会写回 TOML。桌面端需要让用户编辑敏感内容开关、静默关键词、静默
时段和固定 UTC 偏移，同时不能把运行时修改表现成持久配置。

服务端对关键词数量与字节、静默窗口数量与 `HH:MM`、时区偏移都有边界。客户端既要在输入
附近指出错误，也必须把守护进程响应视作不可信协议输入，避免异常响应把超量字段带进 egui。

## 决策

- `maild-client` 公开与服务端一致的 rules 校验：最多 128 个关键词、单项 256 UTF-8 字节，
  最多 32 个静默时段，时间使用两位 `HH:MM` 且起止不能相同，固定偏移为
  `-1440..=1440` 分钟；
- typed `settings` / `set_settings` 在网络边界校验响应。更新请求先校验 patch，成功响应必须
  明确返回 `persisted: false`；`maild-app::ConnectionHandle` 对 generic actor 请求执行同样
  的入站和出站检查；
- 桌面状态同时保存服务端基线和可编辑草稿。应用时只发送相对基线变化的字段，成功后用服务端
  返回的完整 rules 替换基线和草稿，不根据本地 patch 猜测结果；
- 加载和应用各使用 generation。每次最多一个设置请求，离开后的旧结果不能覆盖重新打开的
  页面；失败保留用户修改并显示有界诊断；
- 页面首屏固定展示“仅对当前 maild 进程生效”，成功态固定写明“未写入 TOML”。应用按钮位于
  内容区底部，规则列表独立滚动；页面不会自动保存；
- 未应用修改离开时确认。应用结果尚未确认时不能返回收件箱，关闭窗口则需要再次明确确认；
- `⌘/Ctrl+S` 应用，Escape 请求返回收件箱。egui 绘制阶段只产生意图，网络工作继续在独立
  Tokio runtime 中执行。

设置页不读取或展示账户密码、SMTP 凭据和 bearer token。settings 持久化需要版本化文件、
原子写入与权限策略，不在 M3-06 中隐式加入。

## 后果

- 用户能明确区分“当前已生效”和“重启后仍存在”，不会把运行时规则误认为配置文件修改。
- 只发送变化字段，保留 JSON-RPC 的部分更新语义，也避免并发调用无意覆盖未编辑字段。
- 若未来协议允许持久化，必须新增明确的用户动作和协议契约，不能复用当前运行时成功文案。

## 验证

- shared client 测试覆盖关键词、时间、时区和 `persisted: false` 边界；
- settings reducer 测试覆盖差异 patch、权威回填、失败保留、过期结果、校验定位与离开确认；
- 420/800/1280 三档无窗口绘制覆盖长列表和快捷键；
- macOS 实际窗口通过回环 HTTP 接入临时 maild，验证现值加载、开关修改、固定应用栏、成功
  提示和脏修改返回确认；`maildctl settings` 独立确认修改已进入守护进程运行时。
