# ADR-0008：M3.5 使用 SQLite Online Backup 创建一致快照

- 状态：Accepted
- 日期：2026-08-20
- 适用范围：M3.5 SQLite 备份与恢复边界

## 背景

maild 的 store 使用 WAL。守护进程运行时直接复制 `.sqlite3`，或分别复制数据库、`-wal` 和
`-shm`，不能保证三个文件来自同一事务时点。简单文件复制还可能漏掉尚未 checkpoint 的邮件和
OTP 去重标记。

恢复的风险高于备份：仓库目前没有单实例或维护锁。即使替换文件前看到数据库暂时未锁定，守护
进程仍可能在检查后启动，或者继续持有旧 inode 并写入，从而让运行状态与路径上的新数据库分叉。

## 决策

- 新增显式维护命令：

  ```text
  maild backup --database <SOURCE.sqlite3> --output <DEST.sqlite3>
  ```

  现有 `maild [config.toml]` 守护进程入口保持不变，但精确相对文件名 `backup` 成为保留字；
  该极端情况可写成 `maild ./backup`。命令直接接收数据库路径，不解析可能包含凭据的 TOML，
  也不猜测相对 `db_path` 的工作目录。
- 源必须是现有普通文件且为当前 maild schema；备份不会迁移或修补源数据库。未来版本、旧版本
  和结构漂移都 fail-closed。
- 使用 SQLite Online Backup API，通过独立只读连接每次复制 100 页、每步暂停 10ms。持续
  `BUSY/LOCKED` 30 秒时取消；有复制进展即可继续，不给大型数据库设置固定总时限。
- 目标父目录必须已存在。命令先解析并固定规范化父目录；Unix 下解析后的目录必须是当前用户
  拥有、不可被组或其他用户写入的目录，路径祖先也不能提供可替换入口（root sticky 目录除外）。
  先在同一目录创建权限受限的随机临时文件，完成复制后校验当前 schema 和
  `PRAGMA quick_check(10)`，关闭 SQLite 连接并 `sync_all`，最后以 no-clobber 方式发布并
  fsync 目标目录。
- 已存在的目标永不覆盖，也不提供 `--force`。所有发布前错误由临时文件 guard 清理，目标路径不会出现
  半成品；进程被强制终止或主机崩溃时可能留下 `.maild-backup-*` 隐藏临时文件，可在确认没有备份
  命令运行后人工删除。发布后目录 fsync 若失败会明确报告“目标已存在但持久性未确认”，不会把
  完整备份静默删除或误报成未创建。
- Unix 临时文件和最终备份权限为 `0600`。备份不压缩、不加密；运维者仍负责目标目录权限、磁盘
  空间和备份介质安全。
- 同一用户身份下的其他进程属于本地维护信任域；它们本就能读取/删除该用户的源库与备份。命令
  不承诺抵御相同 uid 在备份期间主动替换随机临时路径，但通过目录 owner/写权限检查排除其他
  普通用户进入这一竞态。

本切片不实现恢复。恢复前必须先建立跨 daemon 与维护命令的单实例/维护锁；之后恢复流程还需要
独立决策“备份校验 → 保存当前库回滚副本 → 原子替换 → 目录持久化”，不得把文件覆盖夹进本命令。

## 后果

- daemon 运行期间也能取得包含 WAL 最新提交的一致 SQLite 快照，且不占用进程内 `Store` mutex；
- 备份是只新增文件的可回滚操作，失败不会迁移或修改源数据库的逻辑内容，也不会覆盖既有文件；
  SQLite 的只读 WAL 协调仍可能更新 `-shm` 共享内存字节，因此不承诺所有 sidecar 逐字节不变；
- 运维调用必须明确传入实际数据库路径。配置中的相对 `db_path` 仍相对 daemon 的启动目录，调用
  者需要先解析为同一文件；
- 当前没有自动保留、清理、压缩、远端上传或定时调度，避免在备份正确性之外引入删除与凭据面。

## 验证

`tests/store_backup.rs` 覆盖：

- 源 store 仍打开且 WAL sidecar 含数据时，长正文、schema、邮件和 OTP 标记进入备份；
- `quick_check` 通过，源 store 仍可读取，Unix 最终权限为 `0600`；
- 已有目标被拒绝且原字节不变；
- 旧 schema 源被拒绝且不迁移；
- 额外索引页损坏会在复制后的 quick_check 被拒绝，不生成目标或遗留临时文件；
- quick_check/SQLite 诊断中的控制字符和超长文本不会注入或放大 CLI stderr；
- Unix 不安全目标目录 fail-closed；
- `maild backup` 的成功输出、参数错误退出码、路径控制字符转义和二次 no-clobber 行为。
